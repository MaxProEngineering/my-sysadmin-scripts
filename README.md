# Учебный курс “Системное администрирование”: Практическая работа

Содержание репозитория:

script.sh — это написанный на языке командной оболочки Bash текстовый файл, который сначала проверяет наличие самого файла системных логов /var/log/syslog (в данном файле фиксируются сообщения от ядра, служб и приложений), а затем извлекает из него все строки, содержащие слова "error" или "fail" и сохраняет их в файл report.txt (в консоль же данный скрипт выводит информацию о количестве таких строк). 

sample_output.txt — это текстовой файл, в котором содержатся первые 5 строк из отчёта report.txt (при этом, в самом отчете report.txt собраны все строки, содержащие слова "error" или "fail" из файла системных логов /var/log/syslog).

Dockerfile — это файл с инструкциями, по которым Docker собирает образ. Образ создается на базе Ubuntu 22.04 с установкой Python 3. Скрипт script.sh копируется в системную директорию и делается исполняемым. При запуске контейнера: скрипт стартует и активируется HTTP‑сервер на порту 8080 (контейнер слушает 8080 и отдаёт файлы своей рабочей директории). 

docker-compose.yml — это конфигурационный файл, который используется Docker Compose для сборки и запуска сервиса app из текущей директории с монтированием системной папки логов /var/log хоста в контейнер в режиме только чтения.

my-app (содержится в папке nginx_config) — это конфигурационный файл веб-сервера Nginx, который настроен как reverse proxy (обратный прокси-сервер) с поддержкой SSL/TLS-шифрования. В файле содержится конфигурация виртуального хоста (для Nginx), который автоматически принудительно перенаправляет всех пользователей с обычного HTTP (порт 80) на защищенное HTTPS-соединение (порт 443). Также виртуальный хост принимает HTTPS-запросы с использованием SSL-сертификатов my-app.crt и my-app.key. Весь входящий внешний трафик хост перенаправляет на локальное приложение, которое работает на порту 8080.

my-app.service (содержится в папке systemd) — это конфигурационный unit‑файл для системного менеджера systemd, который превращает контейнер в полноценную фоновую системную службу с возможностью управления им с помощью стандартных команд. Контейнер запускается сразу после запуска Docker. В случае ошибки, контейнер автоматически перезапускается.

Также подготовлен отдельный новый скрипт к ДЗ №1 и размещен в папке HW1_Additional_Script:  
Описание дополнительного скрипта: selectedTimeIntervalErrors_script.sh  
Скрипт ищет в системном журнале строки с ошибками только за нужный интервал времени (например, с "2026-10-11 09:45" до "2026-10-11 15:10") и сохраняет их в отчёт selectedTimeIntervalErrorsReport.txt. При этом, в консоль выводится информация об общем количество строк с ошибками (из заданного временного интервала), а также последние 20 строк с ошибками (также из заданного интервала).   
Подробная справка по данному скрипту выводится командой ./selectedTimeIntervalErrors_script.sh -h  
Также в папке HW1_Additional_Script содержится отчет после выполнения скрипта: selectedTimeIntervalErrorsReport.txt
